운영 사이트: https://www.paceupcareer.com

설계 근거와 남은 위험은 `docs/admin-local-db-mcp-poc-decisions.md`, 사용법은 `mcp/README.md`, 비개발자용 설치 안내는 `docs/admin-mcp-desktop-extension-guide.md`를 본다.

## 운영에서 확인한 것 (2026-11-24)

- 관리자 로그인(Clerk 동의 화면), 목록 조회, 한 건 조회, 수정 제안, 미리보기 페이지(어드민 로그인 상태에서만 열림), 잘못된 입력 거부(다른 사이트 링크, 보이지 않는 제어 문자, 없는 ID, 없는 제안 번호), 로그아웃(권한 취소, 키체인 항목 삭제).
- 수정 적용과 원복: 마지막 배너의 설명 끝에 표식을 붙였다가 원래대로 되돌렸다. 홈 화면에 즉시 반영됐고 표식이 보인 시간은 약 2초, 최종 값은 원본과 일치했다. 감사 기록 2건 생성. 같은 제안의 재적용은 거부됐다.
- 일반 사용자 계정: MCP 목록·조회·수정 제안이 서버에서 403(Forbidden)으로 거부됐다. 쿠키만, 또는 Clerk 세션 토큰을 Bearer로 쓴 `/api/mcp/*` 호출은 401, `/admin` 화면과 미리보기는 첫 화면으로 되돌려졌다.
- 운영 서버 위조 토큰 시험(읽기 전용): 운영과 같은 발급자·대상·키 이름·client ID·권한 범위를 모두 맞추고 서명만 일회용 키로 만든 토큰, 개발 값 토큰, 만료, 수명 초과, 형식(typ) 다름, 알고리즘 바꿔치기(HS256), 쓰레기·20KB 문자열을 4개 경로에 보내 모두 401. 서명 없는 토큰(alg none)은 Vercel 방화벽이 앞단에서 403으로 차단. CORS 허용 헤더 없음, `no-store`.
- 서버의 `NEXT_PUBLIC_APP_URL`이 맞다: 수정 제안에 미리보기 링크가 나왔다(주소가 API 주소와 같을 때만 보인다).
- 개발 프로필이 운영 Clerk 발급자·client ID를 받아들이는 약점(localhost 프로그램이 운영 관리자 토큰을 받을 수 있음)을 엣지 케이스 시험으로 찾아 막았다.

## 남은 일

### 1. 운영 흐름 확인 (관리자·일반 계정으로 직접)

- [x] 관리자 로그인과 목록 조회
- [x] 일반 사용자 계정은 403으로 막힌다
- [x] 수정 제안 → 미리보기 → 적용 → 원복, `McpAuditLog` 기록 (적용 결과에 감사 기록 ID가 나온다)
- [ ] 실제 개발 환경 토큰이 운영 서버에서 거부되는지(그 반대도) 로그인된 실제 토큰으로 확인한다. 위조 토큰 시험은 일회용 키 서명이라 이 항목을 대신하지 못한다.
- [ ] 로그인 취소 후 최대 305초 안에 접근이 막힌다.
- [ ] 새 기기 로그인(이메일 인증 코드)과 비밀번호 변경(재인증)이 정상이다 (Clerk 업데이트 적용 후 확인).

### 2. 켜기 전에 정할 것

- [x] 요청 횟수 제한: 시범 단계(관리자 몇 명, 홈 배너만 수정)에서는 필요하지 않다고 판단했다. 인증 없이는 모든 경로가 막히고, 토큰은 5분, 수정은 미리보기를 거친 한 건씩이며 감사 기록이 남고 Vercel 방화벽이 앞단에 있다.
- [ ] 관리자가 늘거나 강의·가격 같은 데이터로 기능을 넓히기 전에 Vercel 방화벽 규칙으로 `/api/mcp/*`에 IP별 분당 요청 수 제한을 추가한다 (코드 변경 없이 대시보드에서 가능).
- [ ] 같은 Clerk 발급자를 쓰는 다른 서비스가 이 client ID와 권한 범위를 허용하지 않는지 조사한다 (설계 문서의 켜기 전 조사 항목).

### 3. 확장 파일 배포

- [x] `mcp/`에서 `npm run build:mcpb`로 `.mcpb`를 만든다 (esbuild로 서버를 파일 하나로 묶고, 로그인 저장용 `@napi-rs/keyring` 네이티브 파일을 macOS 2종·Windows 2종 넣는다. 잠금 파일의 해시로 검증).
- [x] macOS에서 설치하고 Claude 새 채팅에서 로그인·조회를 확인했다. 확장은 Claude 내장 Node.js로 실행되고, 로그인은 키체인에 `production:local-agent-mode-pacemaker-admin`으로 저장된다.
- [ ] Windows에서 설치와 로그인·조회를 확인한다 (파일에는 Windows용 바이너리가 들어 있지만 시험하지 못했다).
- [ ] 새 `.mcpb`를 이전 버전 위에 설치할 때 덮어쓰는지, 먼저 지워야 하는지 확인한다.
- [ ] 직접 만든 확장이 자동으로 업데이트되는지 확인한다 (안 되면 새 파일을 매번 전달해야 한다).
- [ ] 회사 Claude 설정에서 확장 설치가 막혀 있지 않은지 확인한다.
- [ ] 선택: 서버가 최소 지원 버전을 알려 주고, 낮은 버전의 확장이 "새 버전을 설치하세요"라고 안내하게 한다.

새 `.mcpb`가 필요한 경우: 도구 추가·변경, 로그인 방식 변경, 서버 응답 형태 변경처럼 MCP 프로그램 자체가 바뀔 때. 서버 경로만 바뀌는 변경은 웹사이트 배포로 모두에게 반영된다. 관리자가 늘고 업데이트가 잦아지면 서버에 원격 MCP를 두는 방식(Claude 커넥터)을 검토한다.

## 참고

- 환경변수 6개: `MCP_OAUTH_CLIENT_ID`, `MCP_API_JWT_ISSUER`, `MCP_API_JWT_AUDIENCE`, `MCP_API_JWT_KEY_ID`, `MCP_API_JWT_PRIVATE_KEY`, `MCP_API_JWT_PUBLIC_KEY`. 하나라도 비면 `/api/mcp`가 503으로 실패한다. 개발·운영의 발급자, 대상, 키는 서로 달라야 한다.
- 변수 값을 바꾼 뒤에는 재배포해야 반영된다.
- 키 교체: `MCP_API_JWT_KEY_ID`와 두 키를 함께 바꾸고 재배포한다. 발급된 API 토큰은 무효가 되고, MCP는 401을 받으면 Clerk 토큰으로 다시 교환한다.
- Clerk 작업 방법: 권한 범위 생성은 대시보드(OAuth applications → Scopes)에서만 가능하고, OAuth 앱 생성과 수정은 `clerk api /oauth_applications ... --instance <운영 인스턴스 ID>`로 가능하다. 이 CLI는 `--instance prod`가 아니라 인스턴스 ID로 지정해야 운영에 접근한다. 운영 인스턴스 ID는 `clerk apps list`에서 확인한다.
- 리디렉션 주소가 `127.0.0.1`인 이유: 로그인을 마친 관리자 본인의 브라우저가 그 컴퓨터에서 실행 중인 MCP 프로그램으로 돌아오는 방식이다(RFC 8252). 운영에서도 그대로 동작한다. 포트 `53134`가 이미 쓰이면 로그인이 실패한다.
- 운영 앱이 로그인 정보를 저장하는 이름은 MCP 앱이 알리는 이름에 따라 정해진다. 확장은 `local-agent-mode-pacemaker-admin`, 직접 등록한 Claude Code 등은 각자의 이름이다.
